# Arkpedia dynamic art assets

Animated outfit art for Arkpedia: the dynamic illustrations ("dynamic art") of the Arknights Global client, and of the CN client for outfits Global does not have yet, as Spine 3.8 models the site's focused artwork view can play. Stats, skin records and everything else stay in `arkpedia-data`; this repository holds only the animation files and where each came from.

Scope: every skin in the EN `skin_table.json` that has a `dynIllustId` (88 as of client `26-09-23-17-49-43_b9cc4a`: 64 outfits and 24 default Elite 2 artworks), and every skin in the zh_CN one that Global's plan does not have, from the CN client (8 as of CN client `26-09-22-07-47-20_6c71fa`: 6 outfits and 2 Elite 2 artworks). When Global's client carries one of those, its Global bundle is built into a new folder and the manifest moves to it; the CN folder stays published. The outfits with a `dynEntranceId` also carry their entrance: the sequence the game plays before the illustration, with its soundtrack. Each model also carries the illustration prefab's own mesh layers (skies, windows, frames, glows the game draws with the skeleton) that can be drawn exactly as the game draws them, including those drawn with the game's effect shaders (flow distortion, dissolve, ramps, vertex disturbance), whose parameters and textures are carried as data. `sp_` variants, the client's particle systems and the effects no shader description covers are not included; `layers.json` records per model what was left out and why. The particle systems' export (`layerParticles.json`, below) is in trial runs and not part of any folder yet.

## Layout

```
manifest.json
sync-failures.json                          (bundles that could not be built, see below)
models/<slug>/<md5_12>/model.json
models/<slug>/<md5_12>/skeleton.skel        (or skeleton.json)
models/<slug>/<md5_12>/skeleton.atlas
models/<slug>/<md5_12>/page0.webp           (page1.webp, ... for multi-page atlases)
models/<slug>/<md5_12>/entrance.skel        (or entrance.json; only for a skin with a dynEntranceId)
models/<slug>/<md5_12>/entrance.atlas
models/<slug>/<md5_12>/entrance-page0.webp
models/<slug>/<md5_12>/entrance.mp3         (its soundtrack, 160 kbit/s)
models/<slug>/<md5_12>/layers.json          (the illustration prefab's mesh layers, see below)
models/<slug>/<md5_12>/layer0.webp          (layer1.webp, ...: their textures)
models/<slug>/<md5_12>/layerParticles.json  (the particle systems, see below; written only by trial runs so far)
particle-coverage.json                      (how many particle systems each folder's export carries, see below)
```

- `slug` is the skinId with `@` and `#` replaced by `_` (`char_113_cqbw@epoque#7` becomes `char_113_cqbw_epoque_7`).
- `md5_12` is the first 12 hex digits of the source bundle's md5 in the client's `hot_update_list.json`. When the game ships a changed bundle it gets a new folder. A folder is never deleted, and its files change in one case only: when the layers' format grows (model.json's `layersVersion` is older than the sync's), the sync exports that folder's layers again from the same bundle, in place: `layers.json`, its `layer<N>.webp` and model.json's `layers` and `layersVersion`. The skeleton, atlas, pages, entrance and soundtrack stay byte for byte. Every file ever written stays at the commit that wrote it, so a URL pinned to a commit keeps working, and a reader of the older format keeps reading what it read before (see `layersVersion` below).

`manifest.json` names the current folder of each skin:

```json
{ "schemaVersion": 1, "server": "en", "resVersion": "<Global's client list>",
  "resVersions": { "en": "<Global's client list>", "cn": "<CN's client list>" },
  "models": { "char_1044_hsgma2#2": "models/char_1044_hsgma2_2/b1259edb8fff/model.json" } }
```

`model.json` describes one folder:

| Field | Meaning |
| --- | --- |
| `skinId`, `dynIllustId` | The skin_table ids. Elite 2 art is `char_X#2`; outfits are `char_X@group#N`. |
| `spineVersion` | Read from the skeleton itself (always `3.8.99` so far). Needs the Spine 3.8 runtime. |
| `skeleton` | `skeleton.skel` (`format: "binary"`) or `skeleton.json` (`format: "json"`), with `bytes` and `sha256`. |
| `atlas` | `skeleton.atlas`, with `bytes` and `sha256`. |
| `textures` | One entry per atlas page, in order: `page<N>.webp`, `width`, `height`, `bytes`, `sha256`. |
| `premultipliedAlpha` | Always `true`: render with premultiplied alpha. |
| `animations` | Animation name to duration in seconds (3 decimals). Every model has `Idle`, which the validator requires. The other names differ per model: `Interact` and `Special` are common, and a few have `Start`. |
| `bounds` | `x`, `y`, `width`, `height` of the setup pose with `Idle` applied at time 0, in skeleton units. Frame the camera from this; the skeletons' own width and height are 0. |
| `mixes` | The game's own crossfade table (`from`, `to`, `duration` in seconds), when the bundle has one. |
| `dynEntranceId` | The skin_table's `dynEntranceId`, or `null`. The validator requires `entrance` exactly when this is set, so an entrance cannot go missing quietly. |
| `entrance` | `null`, or the entrance: `skeleton`, `atlas`, `textures` (`entrance-page<N>.webp`), `animations` (one, `Start`, 8-23 s), `bounds`, `camera` and `audio` (`entrance.mp3` with `duration`, or `null`). It is drawn in the illustration's own coordinates. The game then plays the illustration's short `Start` and loops `Idle`. |
| `entrance.camera` | The camera the game plays the entrance through, or `null` when its prefab names none: `frames`, `[t, centre x, centre y, visible height, roll]` in skeleton units and degrees from 0 s (sampled at 30 fps, points a straight line reproduces within half a unit dropped; interpolate linearly), and `fades`, the full-screen quads that hide its cuts and flash at the end, as `{color: [r, g, b], keys: [[t, alpha]]}`, and `handover`, the colour the controller hands over to the illustration through (`_params.fadeColor`). Decoded by `scripts/entrance_camera.py` from the prefab's Animators (Mecanim streamed, dense and constant curves) through the whole transform chain; a camera it cannot reproduce fails the model. Particle systems and other effects are not included. |
| `layers` | `layers.json` with `bytes` and `sha256`, or `null` for a bundle without an illustration prefab (none so far). Always present. |
| `layersVersion` | What `layers.json` holds: `3`, plain, effect and tilted layers, with integrated scroll offsets (below); `2`, plain and effect layers; absent or `1`, plain layers only (folders written before effects, until the sync exports their layers again). |
| `source` | `server` (`en` for Global, `cn` for CN), the client `bundle` path, its full `md5` and the `resVersion` it was downloaded from. |

### layers.json

The illustration prefab draws more than its skeleton: MeshRenderers next to it (mostly under `General Effects`) hold backdrops and effects, and groups the illustration controller switches with the animation that plays (`Interact/Special/Start/Idle Only Effects`). `scripts/layers.py` exports every one the site can draw exactly as the game does; everything else is listed in `omitted` with its reason, never drawn approximately. Written without indentation (it is mostly numbers).

| Field | Meaning |
| --- | --- |
| `schemaVersion` | `1` (layersVersions 2 and 3 only add members and entries a reader of 1 ignores or skips, so it stays 1). |
| `textures` | The textures plain layers draw, `layer<N>.webp` in order: `width`, `height`, `bytes`, `sha256`, `wrap` (`[u, v]`, each `repeat`, `clamp` or `mirror`), `opaque` (`[u0, v0, u1, v1]`, image-space UV of the part with alpha 8/255 or more, which `bounds` is fitted to). Lossless WebP of the texture as shipped, straight alpha: every shader a layer can have samples it straight (texture x 2 x vertex colour x colour, alpha clamped, blended `SrcAlpha`). The sync measures each one as it measures atlas pages and prints the result; it changes nothing. |
| `effectTextures` | layersVersion 2: the textures only effects sample (an effect layer's main texture, noise, dissolve, weight and ramp maps), records like `textures`, numbered on from them (`layer<N>.webp` throughout, one index space). A reader that does not draw effects never fetches them. |
| `bounds` | The frame the site opens on: the skeleton's bounds joined with the visible part (`opaque`) of every plain layer drawn at Idle's first frame, in skeleton units. Computed with the Spine runtime (bone followers placed from the posed skeleton) and re-checked by the validator. |
| `effectBounds` | layersVersion 2: the same with the effect (and tilted) layers drawn too, each where it shows at its first frame (its `visible`). |
| `separators` | The skeleton's separator slots (SkeletonRenderSeparator) that exist in the skeleton. |
| `draw` | Back to front, sorted as Unity sorts them: sorting layer, sorting order, render queue, distance (farther first), hierarchy order. Each entry is `{"part": k}`, the skeleton's slots from the k-th separator met in the current draw order to the next (a separator starts its part; one part `0` when the skeleton has no parts renderers), `{"layer": {...}}` (a plain layer), in layersVersion 2 `{"effect": {...}}` (a layer drawn with an effect shader; a reader of layersVersion 1 does not know the entry and leaves it out), or in layersVersion 3 `{"tilted": {...}}` (an effect layer whose mesh turns in depth while it moves, below; readers of 1 and 2 leave it out). A moving layer keeps the place its depth gives it at its first frame. |
| `omitted` | Counts of `particles`, `trails`, `skinned` meshes, `hidden` renderers (off and never switched on) and `holders` (effects loaded from the shared `arts/dynchars/effect.ab`, not fetched), and lists of `{name, reason}`: `custom` (a shader no description covers: UV rotation and custom vertex streams set by scripts and particle streams, grab passes, 3D lighting, sprite sheets, an unknown shader...), `externalTexture` (a texture in a shared bundle `shared-bundles.json` does not list or the client list does not carry) and `other` (unknown scripts or animated components, meshes the export cannot read, layers an Erase mask drawn after them paints over...). With particles exported, `particles` counts the systems left out and `particleReasons` lists each with its reason (layerParticles.json, below). |
| `particles` | Only when the particle systems are exported: `null`, or the pointer to layerParticles.json (below). |

A layer:

| Field | Meaning |
| --- | --- |
| `name` | The GameObject's name (with ` (n)` per material when a renderer has several). |
| `blend` | `alpha` (SrcAlpha, OneMinusSrcAlpha) or `add` (SrcAlpha, One). |
| `texture` | Index into `textures`. |
| `color` | `[r, g, b, a]`: the material colour x 2 x the shader's scales (opacity, a constant dissolve, Disturb Anchor's colour control); `null` when `animation` carries it per frame. |
| `vertices` | `x, y` pairs: skeleton units for a static layer; the bone follower's own units under `follow`; the mesh's own units under `animation`. A mesh whose own depth reaches the screen (a backdrop modelled lying down and turned upright, a floor set at an angle) is flattened through its projection first: the game's illustration camera is orthographic (the controller's `_cameraSize` is its half height, rendered into a `_maxSize` 2048 x 2048 texture; no illustration prefab has a camera of its own), so depth only orders and culls. Under `animation` that is the projection of its first frame when every frame's is that one moved, turned or scaled in the screen's plane, the frames then placing the flattened mesh (a mesh that turns in depth is a tilted layer instead). |
| `uvs`, `triangles`, `colors` | UVs with the material's tiling applied and v flipped to image space; indices into the vertices; vertex colours `r, g, b, a` in 0-1, or `null` (white). |
| `follow` | `null`, or the BoneFollower that places the layer: `bone`, `xy`, `rotation`, `localScale`, `mirrored` (a mirrored parent negates the bone rotation), `parent` (`[a, b, c, d]`, skeleton units per follower unit), `position` (`[x, y]` used when `xy` is off) and `angle` (degrees, used when `rotation` is off). Each frame: `parent x R(rotation) x scale` then the bone's world position, where rotation is the bone's world rotation (negated when `mirrored`, plus 180 with `localScale` and a negative scaleX) and scale the bone's local scale with `localScale`, as spine-unity's BoneFollower does. |
| `animation` | `null`, or the layer's timeline from its Animators' default states: `length`, `loop`, `loopFrom` and `frames`, `[t, a, b, c, d, tx, ty, r, g, b, alpha, active, su, ou, sv, ov]`: the matrix from the mesh's units to skeleton units (to the follower's units under `follow`), the colour, whether it is switched on (0/1, stepped), and the UV map on the exported UVs (`u' = u su + ou`, `v' = v sv + ov`). Sampled at 30 fps and decimated; interpolate linearly. After `length` it wraps to `loopFrom` when `loop` is set, else holds. Animated material properties are read as the clips bind them: a float with 8 in the binding's top four bits, a colour's channels with 4-7, a vector's components (a texture's `_ST`) with 0-3. A property the shader does not declare, the tiling of a texture the material does not bind, and what the effect does not read change nothing the game draws, and are ignored. `states` (optional): `Interact`, `Special`, `Start`: the timeline played from that animation's start when the illustration controller's trigger (`OnInteract`...) puts the layer's Animator in another state; `Idle` restarts the default. |
| `scroll` | `null`, or `[u, v]` image-space UV units per second (the shader's `_MainUSpeed`/`_MainVSpeed` or `_UVTween`, or a UV scroll script's speeds; the script's semantics are inferred from its field names). |
| `only` | `null`, or the animation whose controller group the layer is in (`Idle`, `Interact`, `Special`, `Start`): drawn only while it plays, its timeline from that animation's start. |
| `delay` | Seconds after its clock starts before the layer appears (a `_delayTime` script on its chain), its timeline shifted by as much. |
| `approximated` | `null`, or what a reader that draws plain layers only draws differently from the game. Today only one case: a slight flow distortion (at most 0.06 UV and 40 texels: `FLOW_UNDISTORTED` in `scripts/layers.py`) drawn without its wobble, because leaving the layer out loses a backdrop (Ines's in Under the Flaming Dome, Rosmontis's sky). Such a layer also has `exact`. |
| `exact` | layersVersion 2, only beside `approximated`: `{uvs, shader}`, the same layer drawn exactly, as an effect layer is (the mesh's own UVs and the shader). A reader that knows the shader draws this instead; one that does not draws the approximation. |

An effect layer (`{"effect": {...}}`) has the plain layer's members except `scroll`, `approximated` and `exact` (the shader scrolls), plus `shader`, `visible` and `cull`. `visible` is where it shows at its first frame, `[u0, v0, u1, v1]` in its own UVs (its main texture's alpha, or for an additive one colour x alpha, times its colour and dissolves, sampled over its UVs, undistorted), or `null` when it shows over less than a tenth of them (scattered sparks and stars, or nothing yet; `VISIBLE_COVERAGE` in `scripts/layers.py`): the frame (`effectBounds`) is fitted to it, so a glow faded down, a sky dissolved to wisps or a field of stars does not stretch it. `cull` is `0`, or for a layer that moves the faces it culls as it is drawn (`1` front, `2` back; Unity's front faces wind clockwise on screen, and anticlockwise under a transform that mirrors the mesh (a negative determinant), which Unity culls the other way: that is folded into `cull` here, except a bone follower's own mirroring, which a reader adds; a static layer's culled faces are dropped at export). A plain material whose layer culls faces while it moves is written as an effect layer with a shader that adds nothing, since a reader of plain layers would draw both faces. Its `uvs` are the mesh's own, in Unity's UV space (v up): every texture, the main one included, has its own tiling in `shader`, and v is flipped only when a texture is sampled (image rows run down). `texture` is its main texture, or `null` when the material binds none (Unity's white). Its `color` is the material colour x 2 x the shader's scales, as a plain layer's, except in the `noise` family (Disturb2 has no x2). `scripts/effects.py` reads each shader's parameters; the maths is the shaders' GLSL (GLES3, from the client's `[uc]shaders.ab`).

`shader` (every map is `{texture, st, speed, scroll}`: a texture index, its tiling `[sx, sy, ox, oy]` applied to the mesh UVs, the shader's own scroll `speed` added as `fract(t x speed)`, and a UV scroll script's `scroll` added as `t x scroll`, wrapped only where the texture repeats; Unity UV units per second):

| Member | Meaning |
| --- | --- |
| `family` | `particle`: the Torappu particle shaders (Disturb(CustomData), Ram/Disturb(CustomData), Ram/VertexDisturb(CustomData), Disturb Anchor, Disturb, and Dissolve Add/AB, UVTween, Double, Double edge, Dissolve(CustomData)). `noise`: Disturb2. A reader skips a family or member it does not know. |
| `main` | `{st, speed, scroll, fract}`: the main texture's tiling and scrolls; `fract` samples at `fract(uv)` (the UVTween shaders). An animated layer's frames map the main coordinate as a plain layer's do (`su, ou, sv, ov` on image-space UVs). |
| `distort` | `null`, or the flow distortion: `maps` (one or two), each adding `(texture.r - anchor) x intensity` (`anchor`, `intensity`: `[u, v]`; `texture` null reads 0), the sum times `weight`'s red and green when there is one, plus `constant` (`[u, v]`). `space` `main`: added to the main UV after its tiling, times `main`, and to the first dissolve's UV times `dissolve` (Disturb, Ram, VertexDisturb). `space` `raw`: added to the mesh UV before every tiling (Disturb Anchor, Disturb). |
| `dissolve` | Up to two maps, each with `fract`, `amount` and `border`: alpha x `clamp((texture.r - amount + border x k) / border)`, `k = 1 - roundEven(amount + 0.5)`. A dissolve without a texture is a constant, already in `color`. |
| `edge` | `null`, or the Double edge shaders' edge colour: `{color, pow, epsilon}`; `e = (1 - smoothstep(f / color.a))^pow` mixes the colour towards `color` and its alpha towards `color.a x alpha` (`epsilon`: the AB shader's +0.001 on both sides and e at least 0.001). |
| `ramp` | `null`, or a map whose colour multiplies the texture's (Ram shaders). |
| `vertex` | `null`, or VertexDisturb's vertex noise: a map, `intensity` `[x, y, z]`, `weight` (a map or null) and `matrix` `[a, b, c, d, e, f]`: each vertex moves by `(texture.rgb - 0.5) x weight.r x intensity` in the mesh's own units, mapped into the vertices' units by `matrix`. |
| `animated` | The parameters its Animators drive, in order: `dissolve.<i>.amount`, `.border`, `.st`, `distort.maps.<i>.st`, `.intensity`, `distort.weight.st`, `ramp.st`, `vertex.st`, `vertex.intensity`, `vertex.weight.st`, `edge.color`, and in layersVersion 3 `distort.main` and `distort.dissolve` (the distortion's influences), `main.offset`, `dissolve.<i>.offset`, `distort.maps.<i>.offset` and `vertex.offset`. Their values follow the layer's frames (and its `states`' frames), after the 16 numbers every frame has (18 in a tilted layer): 1 number for an amount, border or influence, 2 for a noise map's intensity, 3 for the vertex intensity, 4 for a tiling, colour or offset; interpolate them like the rest. An offset is `[u, v, speed u, speed v]`: a speed an Animator drives (`_MainUSpeed`, `_DisturbVSpeed`, `_UVTween`...) integrated over the layer's own time, which replaces `t x speed` (still wrapped as `fract`), and the speed then; past the timeline's end it runs on, by what one loop moved per loop when it loops, else at its last speed. (The game multiplies the moving speed by the seconds since the client started, so there a speed that changes makes the texture jump; the integral is the motion the curve describes.) The members above hold their first values; an offset is 0 there and only the frames carry it. Empty for a layer without a timeline, and in `exact`. |
| `mode`, `noise`, `noise1`, `noise2`, `glow` | `noise` family: `noise1`/`noise2` are `[scale, speed, x, y]`; the noise texture's red (at noise 1's scale, scrolled by `fract(t / 20 x speed)`) and green (noise 2's) move the main UV by `0.1 x (r x [x1, y1] + g x [x2, y2])`. `mode` `default`: texture x colour with vertex alpha; `add`: rgb x texture alpha; `glow`: texture.r x colour + texture.g x `glow`. In layersVersion 3 its `animated` may hold `noise1`, `noise2`, `glow` (4 numbers each) and `noise.offset` (the two channels' integrated scroll, `t / 20 x speed`, as `[channel 1, channel 2, speed 1, speed 2]`). |

A tilted layer (`{"tilted": {...}}`, layersVersion 3) is an effect layer (a plain material gets a shader that adds nothing) whose mesh turns in depth while it moves, so that no single flattening holds (Surtr's tumbling stars in Ambience Synesthesia). Its `vertices` are the mesh's own `x, y, z` triples, it always has `animation`, and each frame carries, after the 16 numbers, `e, f`: the depth column of the frame's 2x4 orthographic projection, `x' = a x + b y + e z + tx`, `y' = c x + d y + f z + ty` (its shader's parameters follow those). Its faces are culled by their winding on screen after that projection, each frame, as Unity culls them; a culled layer whose transform would mirror it only part of the time is left out. A vertex noise moves its vertices in 3D before the projection (its `vertex.matrix` is unused).

Every texture an effect needs that sits in one of the client's shared FX bundles (`refs/fx/texture/flow.ab`, `mask.ab`... most noise and dissolve textures do) is exported into the folder like the others; `shared-bundles.json` (written by `scripts/shared_bundles.py`) says which bundle holds which CAB (the texture bundles, and `refs/fx/material.ab` and `sharedbattle.ab`, which hold some particle systems' materials), and the sync fetches a bundle, md5-checked, only when a layer needs it.

### layerParticles.json

The illustration prefab's ParticleSystems as data (`scripts/particles.py`), for the site to simulate as Unity does and draw where they sort among the parts and layers. **Not written by the daily sync yet**: the export runs only with `scripts/sync.py --particles` (trial runs; no `layersVersion` names it until the release that turns it on, which also re-exports every folder). The format below is frozen: the site's simulator and renderer are built against it. `scripts/tests/particle_oracle.py` is the reference simulator: its `Simulation.from_export` reads these records, and a system must simulate from its record exactly as from its typetrees (the round trip, `test/test_particles.py`).

Every system is exported exactly or left out with its reason in layers.json's `omitted.particleReasons` (never drawn approximately). An emitter may stand still, ride a bone follower (`follow`) or move, switch on and off and have its fields and material driven by the prefab's Animators (an emitter timeline, below); sub-emitter parents and children are exported together with their links (`sub`), a parent that draws nothing itself as a spawner (`render: null`); the Trails module and the prefab's TrailRenderers are written as data under the `trail` capability (nothing draws them yet). Reasons that mean the game draws nothing either: `renderer off`, `render mode None`, `render mode None (only its trails)`, `no material`, `never active`, `emits nothing`, `its sub-emitters draw nothing` (`particles.NOT_DRAWN`; `never active` also covers a system a clip only ever switches off; a sub-emitter that draws nothing loses its link, and a spawner left with none draws nothing). A TrailRenderer left out is listed among them with ` (TrailRenderer)` after its name. A `_shakeTrigs` script (a camera shake) on a system's chain changes nothing it draws; the layers' own export still lists it as unknown.

**What layers.json gains** when the export has particles (a reader of layersVersion 1-3 ignores all of it: both deployed site readers skip an unknown draw entry, and read neither the pointer nor the new textures; `test/compat/check.mjs` proves it on the deployed readers' own code):

- `particles`: `null` (no system drawn), or `{file: "layerParticles.json", bytes, sha256, version: 1}`. A reader accepts the file name only if it is exactly that, never a path. The pointer's sha256 is in layers.json, whose sha256 is in model.json, so a pinned commit covers it.
- Draw entries `{"particles": [k, ...]}`: indices into `systems`, a run of systems that sort next to each other with no part, layer or effect between them, drawn in that order where the entry stands. Every system with a `render` is in exactly one run, the runs list them in index order, and two runs are never next to each other. The sort key is the layers' (sorting layer, order, render queue, distance, hierarchy) with the distance moved by the renderer's `m_SortingFudge`: `(layer, order, queue, -(z + fudge), walk)`, z the emitter's depth relative to the root. A material whose queue is 2500 or less draws in Unity's opaque pass, before every transparent entry. A system with a non-zero sorting layer, or drawn before an Erase mask (which would paint over it), is left out.
- `omitted.particles`: the number of ParticleSystem renderers (and TrailRenderers, named with ` (TrailRenderer)` after their path) left out, each with its reason in `omitted.particleReasons`, `[{name, reason}]`, sorted. Without particles it counts every particle renderer, as before (and `omitted.trails` still counts the TrailRenderers the layers do not draw).
- `bounds` and `effectBounds` do not change: particles never frame the view.

**Numbers.** Every non-integer is a float32 (what Unity serializes; derived values such as the emitter matrix and gradient key times are rounded to one), written as the shortest decimal that reads back to it: a reader takes each back to float32 (`Math.fround`), and a value that is an integer is written as one. Integers are counts, indices, enums and seeds. A value equal to its default (the table below) is left out; a reader fills it in.

**Top level**

| Field | Meaning |
| --- | --- |
| `version` | `1`. |
| `unit` | Unity units per skeleton unit (the SkeletonDataAsset's scale). Positions, matrices and sizes in this file are Unity units in the prefab root's space; divide by `unit` for skeleton units. |
| `camera` | `{size, height}`: the illustration controller's `_cameraSize` (Unity units, the game's orthographic half height) and the camera's full height in skeleton units, `2 x size / unit` (and the root's scale). A renderer's `maxSize` is a fraction of it. |
| `controller` | `{fixFxDelay, animTimeFixed}`: the controller's raw flags (`_fixFxDelay` 1 on 82 of 88 models); nothing reads them yet. |
| `textures` | Textures only particles sample, records like layers.json's `textures` plus `phase`, numbered on after `effectTextures` in the same `layer<N>.webp` index space. A material indexes the union `[textures, effectTextures, these]`, so a texture a layer already ships is never written twice; they are never added to `effectTextures` (a reader of layersVersion 2 fetches every one of those and caps them at 128). `phase` is the first group that samples it, in fetch order `idle`, `Start`, `Interact`, `Special`. |
| `materials` | `[{blend, texture, color, shader, custom, cull}]`, below. |
| `meshes` | `[{vertices, uvs, colors, triangles, normals, areaCdf}]` or `{builtin: "quad"}`, below. |
| `systems` | One record per system, in draw order, below. |
| `trails` | Absent, or the prefab's TrailRenderers as data (below; nothing draws them yet). |

**Materials.** `blend` `alpha` or `add`. `texture`: the main texture (an index into the union), or null (Unity's white). `color`: the material colour x 2 x the shader's scales, as for layers. `shader`: the layers' effect description (`shader` of an effect layer, the same members, numbers rounded to 6 decimals as layers.json writes them; `animated` is always empty, a timeline carries animated values). A plain Additive or AlphaBlend material gets the particle family with no stage: `{family: "particle", main: {st, speed: [0, 0], scroll, fract: false}, distort: null, dissolve: [], edge: null, ramp: null, vertex: null, animated: []}`. Every particle has one UV convention: Unity's v-up UV of the quad (or mesh, or texture-sheet frame), with `main.st` (the material's `_MainTex_ST`) applied in the fragment, and v flipped only when a texture is sampled. `custom`: null, or `{inputs: [8 sources]}` for a material with `_HGCUSTOMVERTEXSTREAM_ON`: what the renderer's custom vertex streams put in the 8 values the shader reads (TEXCOORD0.zw, TEXCOORD1.xyzw, TEXCOORD2.xy, in that order), each `"uv.x"`, `"uv.y"`, `"uv2.x"`, `"uv2.y"` (the next texture-sheet frame's UV), `"c1.x"` ... `"c1.w"`, `"c2.x"` ... `"c2.w"` (the Custom Data module's slots) or `0`. The exporter packs the renderer's `m_VertexStreams` in order as Unity does, so a reader never sees Unity's stream enum. What each input adds to (from the shaders' GLSL): Disturb(CustomData) and Ram/Disturb(CustomData): the main UV (0, 1), the dissolve UV (2, 3), `_Amount` (4), the distortion intensities (5), the noise UV (6, 7); Dissolve(CustomData): the main UV (0, 1), the dissolve UV (2, 3), `_DissolveIntensity` (4) and `_BorderWidth` (5). A stage an input drives exists even where the material's own values switch it off (a dissolve whose `_Amount` is 0 still dissolves per particle). `cull`: 0, 1 (front) or 2 (back), the material's.

**Meshes.** Deduplicated by reference. `vertices` x, y, z in the mesh's own Unity units; `uvs` Unity's v-up UV0; `colors` r, g, b, a in 0-1 per vertex or null; `triangles` indices. A mesh a shape emits from also has `normals` (x, y, z per vertex) and `areaCdf` (the cumulative share of each triangle's area, rising to exactly 1: pick a triangle by binary search, then a point by barycentric coordinates); on a mesh only particles are drawn with, both are null. The built-in Quad is `{builtin: "quad"}` (the corners at +-0.5 in x and y, UVs 0-1).

Over-lifetime modules take curve values over the particle's normalized age and keep one random factor per particle for a random curve; start values and emission take them over the loop's normalized time.

**On a bone follower** (`follow`). The follower's frame is its placement as for a layer (`parent x R x scale`, then the bone's world position: spine-unity sets the follower's own scale to 1, or to the bone's with `localScale`). `matrix` is relative to the follower's transform and `rotation` to its rotation. A reader takes the emitter's origin through the placement, and its linear part as the scaling mode says: `hierarchy` and `shape`, through the whole placement; `local`, turned by the placement's rotation alone (`R`; the linear part already holds the system's own scale over the root's, as for a still emitter), since Unity's Local scaling ignores every parent's scale. Local and Shape systems under a follower whose parent mirrors or scales unevenly are left out. `scale` (on particle sizes) stays relative to the root as for a still emitter, the follower's own scale left out: under `hierarchy` with `localScale`, a reader multiplies it by the bone's scale. Positions are then in skeleton units through the placement, as a layer's are.

**Sub-emitters** (`sub`, `child`; particle_oracle.Simulation.link is the reference). A child is simulated in its own space with its own modules, renderer and sort place; it does not play on its own. *Birth*: from the moment a parent particle is born (its link fires with `probability`, rolled once per particle), the child emits from it while it lives, with the child's own rate and bursts timed by the particle's age (the child's start delay is not applied; a child that does not loop stops after its duration; bursts repeat each child duration when it loops); each parent particle keeps its own rate accumulator, and rate over distance counts the parent particle's own movement. *Death*: where a parent particle dies, each of the child's bursts fires once (its probability rolled, its count evaluated at the burst's time). A child particle starts at its parent particle's position at that moment (along the step), the child's shape turned and scaled by the child's own emitter (a local child: that position seen from the child's emitter); its start values are evaluated at the child's normalized time (the parent particle's age over the child's duration; 0 for a death); its inherited velocity is its parent particle's. The child's `maxParticles` caps all of its particles. A parent's prewarm runs its children with it (its `prewarmWindow` adds the children's longest lifetime). The random values: the link's roll is the parent particle's `sub<i>` key and every draw of the link's emission from that particle (a random rate each step, burst rolls and counts, each child particle's 32-bit seed) comes from an xorshift128 seeded with its `subSeed<i>` word (`particle_word`, below), so a child's particles never depend on other parent particles or on the order a reader handles them in. Its draws, each step: the child's rate when it is random between two constants, then for each burst due in the step (loop by loop, burst by burst, cycle by cycle) its probability roll (below 1 only) and its count (when random), then one seed per birth in age order; a death link's generator draws, burst by burst, the roll, the count and a seed per particle of it. The child takes a step's births after moving its own particles, ordered by moment, parent particle (its birth number) and order of birth from it; past the child's `maxParticles` they are dropped.

**Trails** (written as data; nothing draws them yet, and the encoding is checked by nothing that simulates them). A system's `trail`, every member always written: `mode` (`perParticle`, `ribbon`), `ratio`, `lifetime` (a curve value, a share of the particle's lifetime), `minVertexDistance`, `textureMode` (`stretch`, `tile`, `distributePerSegment`, `repeatPerSegment`), `ribbonCount`, `worldSpace`, `dieWithParticles`, `sizeAffectsWidth`, `sizeAffectsLifetime`, `inheritParticleColor`, `colorOverLifetime` and `colorOverTrail` (colour values), `widthOverTrail` (a curve value), `attachRibbonsToTransform`, `splitSubEmitterRibbons`, and `material` (the renderer's second material, an index into `materials`; what a clip drives on the renderer is not read for it). A TrailRenderer (`trails`) is `{name, requires: ["trail"], only, delay, active, follow, emitter, time, minVertexDistance, widthMultiplier, widthCurve, colorGradient, numCornerVertices, numCapVertices, alignment, textureMode, emitting, material, draw}`: its transform as a system's emitter with Hierarchy scaling (still, or a timeline with `tint`, `main.st` and shader columns for what its clips drive), `widthCurve` a curve value, `colorGradient` a gradient G, `alignment` `view` or `transformZ`, and `draw` `[i, n]`, where it sorts among layers.json's draw entries: before entry i, or after the first n systems (not all) of the particle run at i.

**Value encodings.** A curve value is a number, `["r", min, max]` (random between two constants), `["c", scalar, keys]` (a curve times scalar) or `["cc", scalar, minKeys, maxKeys]` (random between two curves, both times scalar). Keys are flat `[t, v, inSlope, outSlope, ...]` (cubic Hermite, slopes per unit time; a stepped slope is null). When a curve does not clamp at both ends, `["w", pre, post]` follows the keys (`["w", minPre, minPost, maxPre, maxPost]` for two curves), each `clamp`, `repeat` or `pingPong`. A colour value is `[r, g, b, a]`, `["r", c0, c1]` (random between two colours), `["g", G]` (a gradient), `["gg", G0, G1]` (random between two gradients) or `["rg", G]` (a random point of one gradient). G is `{c: [t, r, g, b, ...], a: [t, a, ...]}` (times already divided by 65535), plus `fixed: true` for a stepped gradient. Units: radians, sheet fractions, Unity units in the emitter's space.

**Emitter timelines**: `{columns, length, loop, loopFrom, frames, states}`. `columns` names each column in order, never positionally: always `t`, `matrix` (12), `rotation` (4), `scale` (3), `active` (0 or 1, stepped), then only those a clip animates: `speed` (1), `emission.rate`, `emission.enabled`, `emission.distance`, `main.startColor` (4), `main.startSize`, `main.gravity`, `noise.strength`, `velocity.speedModifier`, `shape.radius`, `size.multiplier` (1 each), `trail.color` (4), then `tint` (4, the material colour as `color`), and material parameters under layers.json's names (`main.st`, `main.offset`, `dissolve.<i>.amount`, ...; their widths as there). A frame is those values in that order; interpolate linearly, `active` and `emission.enabled` stepped (a value holds from its frame until the next). `length`, `loop`, `loopFrom` and `states` (`Interact`, `Special`, `Start`: another timeline played from that animation's start, while the illustration controller's trigger holds the Animators in that state) are a layer timeline's: after `length` it wraps to `loopFrom` when `loop` is set, else holds.

- The head: the still emitter's `matrix`, `rotation` and `scale` at that moment (relative to the follower under `follow`), and `active`, whether every GameObject below its action group is on. A GameObject switched off clears the system's particles, as Unity's deactivation does; switched back on, the system plays again from its start.
- The field columns each replace one serialized number of the system while the timeline plays (the same number at every frame where no clip drives it in that state): `speed` simulationSpeed (a reader integrates it: the system's time advances by speed x dt); `emission.rate` and `emission.distance` the rate curve's `scalar` (the number of a constant, the multiplier of `["c"]`/`["cc"]`, the max of `["r", min, max]`); `emission.enabled` (0 stops emitting, live particles live on); `main.startColor` the start colour's max colour (a constant, or the second of `["r", c0, c1]`; a gradient reads none, and such a binding is not written); `main.startSize`, `main.gravity`, `noise.strength`, `velocity.speedModifier`, `size.multiplier` the `scalar` of the start size (x), the gravity modifier, the noise strength (x), the speed modifier and the size over lifetime (x); `shape.radius` the shape's radius; `trail.color` the trail's `colorOverLifetime` max colour (with `trail` only). Start values are read at birth, so a driven start colour or size changes only particles born after it. A field a clip drives that no column carries leaves the system out (`driven by a clip: <field>`); one that changes nothing (a module that is off, a shape without that radius) is not written.
- `tint`, `main.st` and the shader columns are what the clips drive on the renderer's material, with the material's own values where they drive nothing; a driven property that changes nothing the shader draws is not written, any other leaves the system out (`animated material property ...`).
- Sampling: at 30 fps over the clips that move, switch or drive the system, as a layer's timeline (looping clips over their common period after the longest one-shot), plus a frame at each moment a stepped column switches (found to well under 1e-4 s, written to 1e-4 s); frames a straight line reproduces are dropped, to within 1 skeleton unit for the position, 0.5% for the linear part, the quaternion and the scale, 0.004 for colours and 0.1% of the column's largest value for the fields. Positions are written to 1e-4 Unity units, the linear part, quaternion and scale to 5 significant digits. The quaternion keeps the sign nearest the frame before (interpolate, then normalize).
- An emitter nothing moves, switches or drives is still; a system some clip drives keeps a timeline even when its values hold.

**The prewarm window.** A system that prewarms and loops is simulated through its first loop before it shows; only the last `prewarmWindow` W of that loop matters, the longest a particle can live (the highest start lifetime, with every key and every overshoot of a curve between keys), at most the loop's duration: every particle alive at the loop's end was born in it. Where `maxParticles` could bind (the highest rate times W plus every burst of a loop at its highest count is more than `maxParticles`), dropped particles depend on what came earlier, and W is the duration, at most 30 s. A reader simulates the loop's last W at its fixed step.

**Random values** (`particle_oracle`, which a site simulator matches particle for particle): each play of a system draws from one xorshift128 generator, seeded by `seed` or, for a new seed each play, `play_seed(modelSeed, system index, play count)`. The generator draws only system-level values (the start delay, a random rate each step, burst rolls) and one 32-bit seed per particle at its birth; every value of that particle is `particle_random(seed, key)`, the key's index in `RANDOM_KEYS` (its over-lifetime factors, its start values, then up to 16 draws of its shape, then per sub-emitter link i, `sub<i>` and `subSeed<i>` for i 0-7), so a value never depends on which other draws happened; `particle_word(seed, key)`, `mix32(seed ^ mix32(key + 1))`, is the 32-bit word a link's generator is seeded with. A sub-emitter child's particles take their seeds from their parent particle's link generator (above). The hash is Wellons' lowbias32 on uint32; `scripts/tests/test_particle_oracle.py` pins its values.

**Mesh shapes** (`shape.type` `mesh`; particle_oracle `_mesh_point`): `placement` `vertex` picks a vertex (uniformly, or in order with a `spawn` mode other than random), `triangle` a triangle by area (the first whose `areaCdf` reaches a random value; in order with a spawn mode) and a point in it with barycentric weights `1 - sqrt(u1)`, `sqrt(u1)(1 - u2)`, `sqrt(u1) u2`, `edge` such a triangle, one of its three edges and a point along it. The direction is the normal (interpolated with the same weights, normalized), the point moves `normalOffset` along it, and with `useColors` the vertex colour (interpolated) multiplies the start colour. The shape's own transform applies after, as for every shape. The weighting of edges and the order of spawn modes are inferred.

**Coverage** (`particle-coverage.json`, written by `scripts/particle_coverage.mjs <root> --write` from an export): per model folder, `drawn` (the systems the game draws: exported ones with a renderer, and those left out for a reason other than drawing nothing; TrailRenderers are not counted), `exported` (of them, those exported) and `v1` (of those, the ones a reader that knows `sub` but not `trail` draws), and their totals. The validator fails a folder whose export carries fewer than its entry, or counts another `drawn` (for one bundle that number is the bundle's: a change means a reason moved into or out of `NOT_DRAWN`); a folder the table does not have yet (a new bundle) is not checked. `node scripts/particle_coverage.mjs <root>` prints a root's counts against it.

## How the files are made

`scripts/sync.py` runs daily on GitHub Actions (`.github/workflows/sync.yml`) and can be started by hand with a `limit` or a list of skinIds.

1. It reads the EN `skin_table.json` from ArknightsAssets/ArknightsGamedata and the Global client's network config, version file and `hot_update_list.json`, then the zh_CN `skin_table.json` from Kengxxiao/ArknightsGameData and the CN client's (`ak-conf.hypergryph.com`, `ak.hycdn.cn`). Global comes first: CN only fills the skins Global's plan does not have. Each model is downloaded, and its shared shader and FX bundles read, from its own client, and `sync-failures.json` keeps the records of both clients' skins.
2. For each skin with a `dynIllustId` whose bundle (`arts/dynchars/<id>.ab`) the list carries, it skips the bundle if a folder for that md5 already exists. Otherwise it downloads the `.dat` from the client's asset CDN (GET only, one at a time, a 3 second pause between downloads) and checks its size and md5 against the list.
3. It decodes the bundle with UnityPy (plus the LZ4AK patch Arknights bundles need). When anything is to be built, the run first fetches the client's shared shader bundle `[uc]shaders.ab` (734 KB, size and md5 checked against the list, cached under `.cache/shared/`): layer materials name their shaders by reference into it. A layer whose texture sits in a shared FX bundle (`shared-bundles.json`) makes the run fetch that bundle the same way, once (`refs/fx/texture/flow.ab` 10 MB and `mask.ab` 3.6 MB are the usual ones). Without it nothing is built that run, and nothing is recorded as failed. File names come from the bundle, never from the id. The skeleton is the one the illustration prefab (`dyn/arts/dynchars/.../<id>.prefab` in the bundle's container) plays, and its SkeletonDataAsset links it to its atlas. Names alone are not enough: Kal'tsit's boc#6 bundle has an entrance skeleton with exactly the same name as the illustration. Names are used only for a bundle without that prefab, and then entrance (`_Start`, `_Start#N`) and portrait skeletons are left out. Particle textures and effect masks are always ignored. A skin with a `dynEntranceId` also takes the skeleton its entrance prefab (`dyn/arts/dyncharstart/.../<dynEntranceId>.prefab`) plays, never one picked by name, and the soundtrack under `.../dynentrance/<dynEntranceId>/`, exported by UnityPy and encoded as MP3 (lameenc). A missing entrance prefab fails the model.
4. Skeleton bytes are written unchanged. In the atlas only the page name lines change, to `page0.webp`, `page1.webp`, ... (the originals contain `#`, which breaks URLs). Each page is saved as premultiplied, lossless WebP at exactly the size the atlas was packed at. The client ships a page in one of two ways, and each needs different handling:
   - **One RGBA texture** (ASTC, e.g. Hoshiguma's Elite 2): straight alpha with colour under transparent texels. It is premultiplied here. A few ship already premultiplied (Goldenglow's summer#12); both measurements say so, and they are kept as shipped.
   - **An RGB texture plus a separate `[alpha]` mask** (ETC, e.g. Ch'en's Elite 2, Nian's Elite 2): the game's RGB is already premultiplied. The mask becomes the alpha channel and the colour is kept as shipped. Premultiplying again would darken every soft edge and glow.

   Before writing a page, the sync measures it: the colour under fully transparent texels, and how often colour exceeds alpha at alpha 16-63. Straight pages measure about 120-156 and 80-97%; masked pages measure under 0.1 and 5-14%. A page that doesn't match how it was shipped, or measures in between, fails the model instead of being written wrong. The result for each page is printed in the log, in `.cache/sync-report.json` (`pages`) and in the run summary.
5. `scripts/inspect-skeleton.mjs` reads the skeleton with the vendored Spine 3.8 runtime (`vendor/spine-core-3.8/`) to record the animations and bounds, then the layers (`scripts/layers.py`: meshes, materials, Mecanim clips through `scripts/entrance_camera.py`) are exported for its slot names and framed (`inspect-skeleton.mjs <folder> layers`). A skeleton without an `Idle` animation fails the model, because an entrance skeleton has only `Start`. Then the folder is moved into place and `manifest.json` is updated.

A folder whose model.json has an older `layersVersion` (or none) than the sync's (`LAYERS_VERSION` in `scripts/layers.py`) has its bundle downloaded and checked again, and only its layers are exported again into a copy of the folder, which then replaces it in one rename (the first run after a format change does this for every folder: about 434 MB of bundles, once).

A model that fails at any step is skipped and reported. The run still commits the models that worked, then shows as failed so someone looks. The manifest only ever names complete folders. Before anything is pushed the workflow runs the validator and the tests, because a push made with the workflow token does not start the Check workflow.

When a bundle downloads and verifies but can't be turned into a model, the sync records it in `sync-failures.json` (skinId, bundle md5, a fingerprint of the sync code, and the error) and commits the file. Later runs skip that bundle until the game ships a new one (a new md5) or the sync code changes, so a broken bundle isn't downloaded again every day. Skipped bundles show as warnings, and only a new failure marks the run as failed. To retry one by hand, run Sync with it in `only`, or with `retry_failed` for all of them. A download that fails or doesn't match the client list is never recorded, since it may work the next day.

`.github/workflows/check.yml` runs on every push and pull request. It installs the same Python packages as the sync, runs the Node and Python tests, and runs `npm run validate`, which checks every folder on disk (including old ones the manifest no longer names). It checks that each file exists with the recorded bytes and sha256, that the required fields are present, that the folder name matches the skinId and md5, that the atlas pages match the texture list and sizes, that the Spine runtime re-reads each skeleton to the recorded animations and bounds, and that `layers.json` is well formed for the folder's `layersVersion` (every index in range, every texture listed and drawn, a plain layer's texture among `textures`, every effect's shader complete and every map's texture listed, timelines in order), its textures match their records and sizes, its separator slots and bones exist in the skeleton and its `bounds` and `effectBounds` re-frame to the recorded ones; where layers.json points at a `layerParticles.json`, that file is checked in full too (its bytes and sha256, every field, every system with a renderer in exactly one draw run, sub-emitter families whole, every texture, material and mesh used (trail materials count), its textures numbered on and matching their records), and its coverage against `particle-coverage.json`. `shared-bundles.json` is checked to name `refs/fx/` bundles by CAB. The Check also runs the reference particle simulator's tests (`python -I scripts/tests/test_particle_oracle.py`), and the Node tests run the site's two deployed layers.json readers (copies in `test/compat/`) over every committed layers.json with particle runs added, which they must skip without fetching, framing or drawing anything else.

## Run it locally

Python 3.12 and Node.js 22. The scripts have no npm dependencies.

```sh
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/sync.py --dry-run                      # what would be fetched, and how much
.venv/bin/python scripts/sync.py --only 'char_1044_hsgma2#2'    # quote ids: they contain # and @
.venv/bin/python scripts/sync.py --limit 10
.venv/bin/python scripts/sync.py --retry-failed                 # also retry bundles in sync-failures.json
.venv/bin/python scripts/sync.py --bundles ../bundles             # build from local unpacked bundles (<dir>/<slug>.ab), md5-checked
.venv/bin/python scripts/shared_bundles.py                      # rewrite shared-bundles.json (GETs every refs/fx/ bundle, ~55 MB)
.venv/bin/python scripts/sync.py --bundles ../bundles --only 'char_1044_hsgma2#2' --particles   # trial: also layerParticles.json, in a folder the run builds or re-exports
npm run validate
npm test
.venv/bin/python -m unittest discover -s test -p 'test_*.py'
.venv/bin/python -I scripts/tests/test_particle_oracle.py     # the reference particle simulator (PARTICLE_ORACLE_BUNDLE=<unpacked .ab> adds a real bundle)
PARTICLE_EXPORT=<root with models/> .venv/bin/python -m unittest test.test_particles   # also Hoshiguma's checks on a trial export
node scripts/particle_coverage.mjs <root with models/> [--write]   # particle coverage against particle-coverage.json
node --experimental-strip-types test/compat/check.mjs <dir with models/> [--baseline <dir>]   # the deployed readers over exported files
```

Run one sync at a time; the workflow's concurrency group makes sure two never overlap on GitHub.

## Using the files

Load `manifest.json` and the files through URLs pinned to a commit of this repository (`https://raw.githubusercontent.com/arkpedia/arkpedia-l2d-assets/<commit>/...`), never the moving `main`. Raw URLs send `Access-Control-Allow-Origin: *`. A JSON skeleton is fetched as text and a binary one as an ArrayBuffer; branch on `skeleton.format`. Render with the Spine 3.8 runtime and `premultipliedAlpha: true`.

## Size

The first full sync downloads 88 bundles, 434 MB (by the client list's `totalSize`), plus the 734 KB shared shader bundle. The repository will hold about 125 MB of skeletons and atlases plus 290 to 440 MB of lossless WebP pages, about 0.4 to 0.6 GB in all. The layers add about 131 MB (layersVersion 2, built from client `26-09-23-17-49-43_b9cc4a`: 2,248 layers, 1,756 of them with effect shaders, and 1,653 textures in 86 of the 88 models, 0 to 5.4 MB per model, 1.5 MB on average; layersVersion 1 held 61 MB). layersVersion 3 over all 96 models (Global client `26-09-23-17-49-43_b9cc4a`, CN `26-09-22-07-47-20_6c71fa`): 2,558 layers drawn (2,417 in layersVersion 2), 1,957 of them with effect shaders and 10 tilted, and 1,878 textures, 161 MB in all, 9.2 MB more than layersVersion 2 (0.1 MB per model on average, 2.0 MB at most); a `layers.json` is at most 0.7 MB. A run that builds anything may also fetch shared FX bundles its layers need (`refs/fx/texture/flow.ab` 10 MB and `mask.ab` 3.6 MB for most). Later runs only fetch bundles the game changes.
